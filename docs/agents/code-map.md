- Bulk plan/apply (E9, `ae_plan` :618 / `ae_apply` :671): `ae_plan` runs a `bulk`-category op with `dryRun: true`, stores `[{op, args}]` against the returned `fingerprint` (`PlanStore.create`) and returns `{planId, changes}`; `ae_apply` peeks the plan (`PlanStore.peek`), re-runs the op dry to get the current fingerprint, consumes the plan with `PlanStore.take` (expired → `PLAN_EXPIRED`, changed → `PLAN_CHANGED`, gone → `UNKNOWN_PLAN`), then re-runs the op with `dryRun:false`. `ServerOptions.planStore` injects a store. ## Bridge call path

- `AEClient.call(tool, args)` `ae-client.ts:26`; builds job `{protocolVersion:1, id, tool, args, deadline}` :72 (30s timeout :57). Transport failure → `BRIDGE_NOT_LOADED` :103; stall detection rewrites timeouts into a modal-dialog hint. (E14-3) an `AE_BUSY` result (another script running) is retried with exponential backoff (`retry` option, default 4 attempts, 200ms base, 2s cap; `sleep` injectable, `false` disables) before it is returned; each attempt carries a fresh `deadline` (#183).
- (#179) The AE app name comes from `resolveAeAppName(applicationsDir?)` (`osascript-transport.ts`): `AE_APP_NAME`, else the newest install from `discoverAEVersions`, else `aeAppName()`'s default; used by `selectTransport`, `launchAE` and `createBridgeCall`.
- (E14-16 / #157, #159) `OsaScriptTransport` (`osascript-transport.ts`) bounds `DoScriptFile` with `timeoutMs` (env `AE_MCP_SCRIPT_TIMEOUT_MS`, default 120s); a killed call → `AE_BUSY` so the backoff retry runs. `with override` (sdef) is opt-in via env `AE_MCP_SCRIPT_OVERRIDE=1`, off by default. The job file is written to `bridge/jobs/<id>.json`, not `inbox/`: the startup loader polls `inbox/` on a timer and would otherwise steal and delete the job before the trigger reads it.
- `ResultMessage` `protocol/src/messages.ts:24-41`: `{ok:true,result}` | `{ok:false,error:{code,message,hint?}}`. Codes+hints `protocol/src/errors.ts` (`makeError`); E8-5 added `UNKNOWN_JOB`/`AERENDER_NOT_FOUND`, E9-2 added `UNKNOWN_PLAN`/`PLAN_EXPIRED`/`PLAN_CHANGED`, E14-3 added `AE_BUSY`.
- (#198) On a `TIMEOUT`/`BRIDGE_NOT_LOADED` (or a transport throw), `AEClient` first calls `isAeRunning()` (`ae-process.ts`, `pgrep -x 'After Effects'`, option `isAeRunning` injectable); none running → `AE_NOT_RUNNING`. `buildAeContext` (`context.ts`) reports `aeRunning` and the launch fix.
- **`job.tool` IS the operation name** — bridge treats observe tools and `category.action` op names identically.

## Plan store (`packages/server/src/plans.ts`, E9-1)

- `PlanStore<T>` — in-memory store of previewed (dry-run) bulk edits. `create(steps, fingerprint)` → `planId`, `get(planId, fingerprint)` (non-consuming), `peek(planId)` (returns the plan without the fingerprint, so the caller can read its target op), `take(planId, fingerprint)` (consumes on success), `size()`. A plan is valid only while unexpired (`ttlMs`, default 10 min) and the project `fingerprint` still matches; failures are `unknown` | `expired` | `changed`. Expired plans are pruned on `create`/`size` and the oldest are evicted past `maxPlans` (default 20). `now`/`ttlMs`/`maxPlans` are injectable. For E9-2 a `T` is a `BulkStep {op, args}`, and the fingerprint is chosen by each bulk op.

## Job store (`packages/server/src/jobs.ts`, E8-5/E8-6)

- `JobStore` — in-memory registry of long-running jobs (`JobRecord {id, kind, status, createdAt, finishedAt?, progress?, error?, result?}`; `JobStatus = running|succeeded|failed|cancelled`). `start(kind)` → id, `get`/`list` (return copies), `progress(id, {frame, rendered, seconds})`, `succeed`/`fail`/`cancel`; finished jobs are evicted past `maxFinished` (default 50). Consumers: `ae_render` + `job_status` + `job_cancel`.
- `cleanupPartialOutput(output, startedAt)` `render-output.ts` (E8-6) — after a cancel, removes the single output file or the `[####]` image-sequence frames whose mtime is at/after `startedAt`; pre-existing files and directories are left alone.
