## Server tools (`packages/server/src/server.ts`)

- `createServer(options)` :91 — every tool is `server.registerTool(name, config, handler)`.
  - `inputSchema` is a zod raw shape; the MCP SDK validates args against it before the handler runs (`InvalidParams` on failure).
- Existing tools: `check_setup` :217, `ae_context` :233, `ae_project_info` :243, `ae_comp_info` :253, `ae_layer_info` :277, `ae_expression_report` :310, `ae_version_info` :343, `get_selection` :353, `find` :363, `ae_render_frame` :394, `ae_render` :448, `job_status` :520, `job_cancel` :538, `ae_catalog` :562, `ae_do` :580, `ae_plan` :667, `ae_apply` :720. (E14-7 `ae_expression_report` lists every expression-driven property on a comp's layers; E14-6 `ae_layer_info` layers carry `markers` with `time`/`duration`/`comment`; E14-8 the `property.set`/`keyframe.add`/`keyframe.remove`/`keyframe.set_easing`/`effect.set_property`/`effect.set_keyframe` handlers attach a `warning` when the target property is expression-driven, via `aemcpWithExpressionWarning` `handlers.js`.)
- Helpers: `text(value, isError?)` :69 (JSON.stringify → MCP text content), `toResult(ResultMessage)` :73 (ok → text, else text+`isError:true`), `readRenderedFrame(root, file, maxBytes)` :78 (reads a frame the bridge rendered, refusing paths outside `<root>/render`, base64 → image data; `MAX_RENDER_BYTES` 20_000_000 :32), `callRaw(tool, args)` :141 (lazy memoized `AEClient.call`), `capArray` :101 (byte cap `MAX_RESULT_BYTES` 200_000, sets `truncated`).
- Bulk plan/apply (E9, `ae_plan` :618 / `ae_apply` :671): `ae_plan` runs a `bulk`-category op with `dryRun: true`, stores `[{op, args}]` against the returned `fingerprint` (`PlanStore.create`) and returns `{planId, changes}`; `ae_apply` peeks the plan (`PlanStore.peek`), re-runs the op dry to get the current fingerprint, consumes the plan with `PlanStore.take` (expired → `PLAN_EXPIRED`, changed → `PLAN_CHANGED`, gone → `UNKNOWN_PLAN`), then re-runs the op with `dryRun:false`. `ServerOptions.planStore` injects a store. The fingerprint is chosen by each bulk op (E9-2 `bulk.rename` fingerprints the target layers' indices+names; E9-3 `bulk.set_property` fingerprints the targets' current values; E9-4 `bulk.apply_effect`/`bulk.set_expression` fingerprint the effect name / expression plus the targets' current state, `bulk.apply_preset` fingerprints the preset path plus the target indices; E9-5 `bulk.replace_text` fingerprints the targets' current text; E9-6 `bulk.stagger` fingerprints the targets' current times; E9-9 `bulk.remove_unused` fingerprints the sorted ids of the items it would delete; E9-10 `bulk.duplicate_comp` fingerprints the source name plus the requested name/size; E9-11 `bulk.organize_items` fingerprints each requested folder name plus the resolved item ids; E9-12 `bulk.resize_comp` fingerprints the source name plus every requested format).
- `ae_render_frame` (E8-2) runs `render.frame` then returns MCP `image` content (`mimeType: image/png`) plus a JSON metadata text block.
- `ae_render` (E8-5) starts an aerender render as a background job and returns `{jobId}`; `job_status` (E8-5) polls it; `job_cancel` (E8-6) kills the process and removes partial output. `findAerender` :152 uses `options.aerender` or `discoverAerenders(applicationsDir)`, `resolveProject` :161 defaults to the open project's file (from `ae_project_info`) and refuses an unsaved project (`UNSAVED_PROJECT`). A `runs` map :150 keeps each job's `cancel`/`done` so `job_cancel` can abort and await cleanup. See the job store below.
- `ServerOptions` :35 injects `root`, `client`, `operations`, `maxResultBytes`, `settings`, (E8-5) `aerender`, `spawnAerender`, `jobStore`, and (E9-2) `planStore` — used by tests.
- `getSettings()` :79 — lazy `loadSettings({root})`, or `Promise.resolve(options.settings)` when injected.
- Policy (E7-2): `isPermitted(def, settings)` + `batchRunBlock(registry, ops, settings)` `server/src/policy.ts:4,11`. `ae_do` and `ae_catalog` enforce it: read-only hides non-`readOnly` ops, `allowedCategories` filters by category, `batch.run` is checked per sub-op. Rejection uses error code `FORBIDDEN` (added in `protocol/src/errors.ts`).
- eval gate (E7-3): `evalRunEnabled(def, settings)` `policy.ts:24` — `eval.run` is hidden from `ae_catalog` and rejected by `ae_do` (FORBIDDEN) unless `settings.evalEnabled`.
- destructive guard (E13-3/4): in `ae_do` `server.ts:301` — a `destructive` op (or a `batch.run` containing one, via `batchHasDestructive` `policy.ts:60`) first runs `project.increment_save`; a project that has never been saved is refused with error code `UNSAVED_PROJECT`. One increment per call / per `batch.run`. Gated by `settings.incrementBeforeDestructive` (default on, env `AE_MCP_INCREMENT_BEFORE_DESTRUCTIVE`). The path produced by the last successful incremental save is persisted and surfaced by `check_setup` as the `project_saved_version` check (`server.ts`, `setup-checks.ts:65`).

## Bridge call path

- `AEClient.call(tool, args)` `ae-client.ts:26`; builds job `{protocolVersion:1, id, tool, args, deadline}` :72 (30s timeout :57). Transport failure → `BRIDGE_NOT_LOADED` :103; stall detection rewrites timeouts into a modal-dialog hint. (E14-3) an `AE_BUSY` result (another script running) is retried with exponential backoff (`retry` option, default 4 attempts, 200ms base, 2s cap; `sleep` injectable, `false` disables) before it is returned.
- (E14-16 / #157, #159) `OsaScriptTransport` (`osascript-transport.ts`) bounds `DoScriptFile` with `timeoutMs` (env `AE_MCP_SCRIPT_TIMEOUT_MS`, default 120s); a killed call → `AE_BUSY` so the backoff retry runs. `with override` (sdef) is opt-in via env `AE_MCP_SCRIPT_OVERRIDE=1`, off by default. The job file is written to `bridge/jobs/<id>.json`, not `inbox/`: the startup loader polls `inbox/` on a timer and would otherwise steal and delete the job before the trigger reads it.
- `ResultMessage` `protocol/src/messages.ts:24-41`: `{ok:true,result}` | `{ok:false,error:{code,message,hint?}}`. Codes+hints `protocol/src/errors.ts` (`makeError`); E8-5 added `UNKNOWN_JOB`/`AERENDER_NOT_FOUND`, E9-2 added `UNKNOWN_PLAN`/`PLAN_EXPIRED`/`PLAN_CHANGED`, E14-3 added `AE_BUSY`.
- **`job.tool` IS the operation name** — bridge treats observe tools and `category.action` op names identically.

E8-1 `render.frame` saves one PNG via `CompItem.saveFrameToPng`, falling back to the render queue + PNG output module; output defaults to `<queue root>/render/<comp>-<frame>.png`. E8-3 render-queue ops: `render.queue_add` (`RQueue.items.add` + time span), `render.queue_set_output` (`OutputModule.file`/`applyTemplate`), `render.queue_start` (`RenderQueue.render()`, destructive) and `render.status`; helpers `aemcpRequireRqItem`, `aemcpRenderItemInfo`, `aemcpRqStatusName`. E9-2 `bulk.rename` renames layers by literal/regex `match`+`replace`, `prefix`, `suffix` and `numbering` (start/step/padding/position), defaults `dryRun` true, and returns a target `fingerprint`; helpers `aemcpReplaceAll`, `aemcpPadNumber`, `aemcpRenamedLayerName`, `aemcpBulkFingerprint`. E9-3 `bulk.set_property` sets one `value` on a `property` (a `/`-separated path or a name/match name deep-searched) across a single `comp` or a `comps` array, defaults `dryRun` true, reports `skipped` layers lacking the property, and fingerprints the targets' current values; helpers `aemcpBulkComps`, `aemcpSearchProperty`, `aemcpResolveProperty`. E9-4 `bulk.apply_effect` adds an `effect` (match name) to each selected layer via the effect parade's `addProperty`, skipping layers that already carry it (reason `present`); `bulk.set_expression` sets an `expression` on a `property` of each layer (empty string clears and disables it); `bulk.apply_preset` applies a `.ffx` `preset` to each layer via `Layer.applyPreset` (a missing file is `INVALID_ARGS`); all three default `dryRun` true and return a `fingerprint`; helper `aemcpHasEffect`. E9-5 `bulk.replace_text` find/replaces `find`→`replace` (literal, or a regular expression when `regex` is true with `flags`) on the `Source Text` document of every text layer in a single `comp` or a `comps` array, defaults `dryRun` true, reports `skipped` non-text layers, and fingerprints the targets' current text. E9-6 `bulk.stagger` offsets each selected layer's `startTime` (or, when `target: 'keyframes'`, the keyframe times of a `property` on each layer) by `offset` seconds — the same for every target when `mode: 'fixed'`, or `offset * position` for `mode: 'proportional'` (default) — defaults `dryRun` true, omits targets whose time is unchanged, and reports `skipped` layers lacking the keyframed property; shifting keyframes removes and re-adds them, so easing is reset. E9-7 `bulk.set_label` sets the integer `label` colour (0 = none, 1-16) on every selected layer in a single `comp` or a `comps` array, defaults `dryRun` true, omits layers already at that label, and fingerprints the targets' current labels. E9-8 `project.report_usage` (read-only) walks every comp's layer `source` to find items no comp uses (excluding comps and folders) and footage with `footageMissing` true, returning `{unusedItems, missingFootage, counts}`; helpers `aemcpUsedItemIds`, `aemcpUnusedItems` (reused by E9-9), and the shared `aemcpItemType` from `serializers.js`. E9-9 `bulk.remove_unused` (bulk, destructive) deletes every item that no comp uses via `Item.remove()` (never comps/folders), deleting right-to-left so indices stay valid; `MockProject.removeItem` splices the mock project and its folder. E9-10 `bulk.duplicate_comp` (bulk) plans/duplicates a single comp with a new `name` and optional `width`/`height` (defaulting to the source, both validated 1..30000) via `CompItem.duplicate()` plus the read/write `AVItem.width`/`height`; the mock's `MockCompItem.duplicate` clones the layer objects (`Object.create`+`Object.assign`). E9-11 `bulk.organize_items` (bulk) moves items (matched by id or exact name) into named project folders via `Item.parentFolder`, creating a missing folder at the root with `app.project.items.addFolder` (never in dryRun); helpers `aemcpFindItem`, `aemcpFindFolder`. `MockItemCollection.addFolder` creates a folder with an allocated id. E9-12 `bulk.resize_comp` (bulk) duplicates a source comp once per `{name, width, height}` format (all required, sizes validated 1..30000) and resizes each copy.
- Build: `bridge/src/build.ts` prepends polyfills + `job-runner.js` + `serializers.js` + `handlers.js`.

## Plan store (`packages/server/src/plans.ts`, E9-1)

- `PlanStore<T>` — in-memory store of previewed (dry-run) bulk edits. `create(steps, fingerprint)` → `planId`, `get(planId, fingerprint)` (non-consuming), `peek(planId)` (returns the plan without the fingerprint, so the caller can read its target op), `take(planId, fingerprint)` (consumes on success), `size()`. A plan is valid only while unexpired (`ttlMs`, default 10 min) and the project `fingerprint` still matches; failures are `unknown` | `expired` | `changed`. Expired plans are pruned on `create`/`size` and the oldest are evicted past `maxPlans` (default 20). `now`/`ttlMs`/`maxPlans` are injectable. For E9-2 a `T` is a `BulkStep {op, args}`, and the fingerprint is chosen by each bulk op.

## Job store (`packages/server/src/jobs.ts`, E8-5/E8-6)

- `JobStore` — in-memory registry of long-running jobs (`JobRecord {id, kind, status, createdAt, finishedAt?, progress?, error?, result?}`; `JobStatus = running|succeeded|failed|cancelled`). `start(kind)` → id, `get`/`list` (return copies), `progress(id, {frame, rendered, seconds})`, `succeed`/`fail`/`cancel`; finished jobs are evicted past `maxFinished` (default 50). Consumers: `ae_render` + `job_status` + `job_cancel`.
- `cleanupPartialOutput(output, startedAt)` `render-output.ts` (E8-6) — after a cancel, removes the single output file or the `[####]` image-sequence frames whose mtime is at/after `startedAt`; pre-existing files and directories are left alone.
